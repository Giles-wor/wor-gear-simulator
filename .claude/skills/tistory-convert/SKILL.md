# 티스토리 재가공

네이버 블로그 글을 티스토리용 검색형 정보 글로 바꾼다.

핵심 원칙 한 문장: **네이버는 브랜드를 키우고, 티스토리는 검색 자산을 쌓는다.**

정량 기준(이미지 수, 메타 길이, 유사도 상한 등)의 원본은
`tools/tistory/lib/rules.js`다. 숫자가 필요하면 그 파일을 읽고, 여기 값과
어긋나면 `rules.js`를 따른다.

## 절대 규칙

1. **네이버 발행이 끝난 글만 다룬다.** 티스토리를 위해 추가 취재·추가 방문·
   별도 원고 작성을 하지 않는다. 티스토리는 네이버 콘텐츠의 부산물이다.
2. **없는 사실을 만들지 않는다.** 원문에 없는 정보는 창작하지 말고
   `확인 필요` / `방문 당시 기준` / `공식 채널에서 최신 정보 확인 권장`으로 표시한다.
   특히 가격·운영시간·주차 대수·전화번호를 추측해서 채우면 안 된다.
3. **제3의 캐릭터를 만들지 않는다.** 티스토리 운영자도 `김소요`다. 과거 닉네임
   (커피와비틀즈, 밑줄긋는여자, 이러쿵저러쿵, 살림의여왕, 웰컴쩰리, reo COSME,
   기억의밥상, been일기)을 결과물에 쓰지 않는다.
4. **최종 발행은 자동화하지 않는다.** 초안까지만 만든다. 발행은 사용자가 한다.
5. **협찬·체험단 글은 기본적으로 제외한다.** 계약상 타 플랫폼 재게시가 가능한지
   사용자가 확인해 준 경우에만 진행하고, 본문에 협찬 표시 문구를 남긴다.

## 순서

### 1단계 — 옮길 글인지 먼저 판단한다

**우선 대상**: 맛집, 여행지·관광지, 아이와 가볼 곳, 키즈카페·체험시설,
호텔·숙소, 이케아·코스트코 쇼핑 후기, 제품 실사용 후기, 육아용품, 생활용품,
주차·가격·운영시간·준비물 정보가 있는 글, 오래 검색될 정보성 글.

**제외 대상**: 단순 일상 기록, 짧은 감상문, 브랜드 내부 이야기, 개인적인 고민,
시의성이 매우 짧은 글, 정보 가치가 거의 없는 사진 위주 글, 협찬 조건 때문에
재게시가 어려운 글.

제외 대상이면 변환하지 말고 `SKIP: <이유>`만 답하고 끝낸다. 모든 네이버 글을
옮기는 게 목표가 아니다.

### 2단계 — 입력을 모은다

네이버 제목·본문·URL, 장소명/제품명, 지역, 카테고리, 사용 가능한 이미지 목록,
네이버 이미지 수, 그리고 핵심 정보(주소·운영시간·주차·가격·예약·아이 동반
여부·준비물·장점·단점).

원문에서 읽어낼 수 있는 항목은 직접 채우고, 알 수 없는 항목은 비워 둔 채
사용자에게 한 번만 몰아서 물어본다. 답이 없으면 `확인 필요`로 두고 진행한다.

### 3단계 — 재가공한다

중복 콘텐츠로 잡히지 않도록 다음을 **모두** 적용한다.

- 제목을 완전히 바꾼다 (네이버 제목과 유사도 60% 이하)
- 도입부를 새로 쓴다 (네이버 첫 문단과 유사도 45% 이하)
- 문단 순서를 바꿔 검색자가 궁금해할 정보를 앞으로 뺀다
- 개인적인 에피소드는 축약하고, 정보성 문단을 추가한다
- 소제목을 새로 쓴다 (4개 이상)
- 이미지 수를 줄인다 (네이버의 35~50% 수준, 최대 15장)
- 결론을 새로 쓴다
- 답할 수 있는 질문이 있으면 FAQ를 2~6개 붙인다

사실관계와 실제 경험은 그대로 유지한다.

**말투** — 유지: 직접 경험한 사람의 시선, 솔직한 장단점, 소비자로서의 판단,
과장하지 않는 태도, 김소요 특유의 현실적인 결론. 줄일 것: 많은 감탄사, 긴 일상
에피소드, 사진마다 붙는 짧은 문장, 네이버식 말줄임과 반복, 검색과 무관한 사담.

**제목** — 검색어 중심으로 3개 제시한다. 장소명/제품명 + 지역 + 검색자가 실제로
칠 단어를 넣는다. 예: `대전 용호낙지 메뉴 가격 주차 낙곱새 후기`

### 4단계 — 아래 형식 그대로 출력한다

프론트매터 키 이름을 바꾸지 않는다. 검수 도구가 이 형식을 파싱한다.

```markdown
---
title: (1안)
title_alt:
  - (2안)
  - (3안)
meta: (120~160자)
tags: (5~10개, 콤마 구분)
category: (아래 카테고리 체계 중 하나)
hero_image: (대표 이미지 파일명)
naver_url: (발행된 네이버 글 URL)
sponsored: false
internal_links:
  - (연관 기존 티스토리 글 URL, 실제로 존재하는 것만. 없으면 줄 삭제)
---

(본문)
```

본문 소제목 순서 — 해당 정보가 없는 항목은 **억지로 만들지 않고 생략한다**:

도입부 → 핵심 정보 요약 → 직접 방문하거나 사용한 후기 → 가격 또는 메뉴 →
주차와 접근성 → 아이 동반 여부 → 좋았던 점 → 아쉬웠던 점 → 추천 대상 →
FAQ → 최종 정리

세부:

- `핵심 정보 요약`은 마크다운 표(`| 항목 | 내용 |`)로 만든다
- 가격·운영시간 섹션 제목이나 본문에 시점을 붙인다. 예: `(2026년 7월 방문 당시 기준)`
- 이미지는 `![대체텍스트](파일명)` 또는 `![대체텍스트](파일명 "캡션")`
- FAQ는 `### Q. 질문` + 답변 문단. 원문에서 답할 수 있는 질문만
- **광고 코드를 넣지 않는다.** 광고 위치는 렌더러가 자동으로 표시한다
- 내부 링크는 사용자가 준 후보 목록에 실제로 있는 URL만 쓴다. URL을 지어내지 않는다
- 네이버 원문 URL이 있으면 본문 끝에 한 번 넣는다

### 5단계 — 검수하고 HTML로 만든다

초안을 파일로 저장한 뒤 CLI로 검수한다. 사람 눈으로 놓치는 항목을 잡아준다.

```bash
node tools/tistory/qa-cli.mjs check <초안.md> --naver <네이버입력.md> --out <출력디렉터리>
```

`--naver`에 넘길 입력 파일은 `node tools/tistory/qa-cli.mjs init <경로>`로
템플릿을 만들어 채운다. `--out`을 주면 티스토리 HTML, 제목 후보, 태그,
메타 설명, 이미지 계획, metadata.json이 생성된다.

`[수정]` 항목이 하나라도 있으면 초안을 고치고 다시 돌린다. 종료 코드 1은
발행 불가다. `[확인]`은 판단해서 넘어갈 수 있고, `[직접]`은 사용자가 봐야 한다.

검수를 통과하면 결과를 사용자에게 요약해 전달한다: 제목 후보 3개, 메타 설명,
태그, 대표 이미지, 이미지 수, 광고 위치, 그리고 남은 `[확인]`/`[직접]` 항목.
**발행하지 않는다.**

## 카테고리

| 대분류 | 하위 |
| --- | --- |
| 굳이 가봄 | 여행, 아이와 가볼 곳, 숙소 |
| 맛집카페 | 맛집, 카페 |
| 굳이 사봄 | 생활용품, 육아용품, 쇼핑, 이케아·코스트코 |
| 정보정리 | 이용방법, 주차·예약, 비교·팁 |
| 예전 기록 | 기존 티스토리 글 보관 |

너무 세분화하지 않는다.

## 시간 예산

글당 추가 작업 10분 내외가 목표다. 전체 콘텐츠 작업 시간의 10~20%를 넘기지
않는다. 티스토리 때문에 네이버 업로드나 영상 제작 일정이 밀릴 상황이면
**티스토리 작업을 생략하는 것이 맞다.** 이 판단을 사용자에게 상기시킨다.
