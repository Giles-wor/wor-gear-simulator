# 티스토리 재가공 도구

소비요정 김소요의 네이버 블로그 글을 티스토리(thesimplethings.tistory.com)용
검색형 정보 글로 재가공하는 도구다.

> 네이버는 브랜드를 키우고, 티스토리는 검색 자산을 쌓는다.

로컬 전용 도구다. 어디에도 배포되지 않는다.

## 무엇이 자동이고 무엇이 아닌가

문장을 다시 쓰는 일은 클로드가 한다. 도구가 하는 일은 그 앞뒤다.

| 단계 | 담당 |
| --- | --- |
| 옮길 글인지 판단 | 클로드 (규칙은 도구가 제공) |
| 네이버 원고 → 티스토리 원고 재작성 | 클로드 |
| 티스토리 HTML 생성 | 도구 |
| 광고 위치 3곳 표시 | 도구 |
| 이미지 순서·대표 이미지 정리 | 도구 |
| 품질 검수 15항목 | 도구 |
| **발행** | **사람. 자동화하지 않는다.** |

## 쓰는 방법 1 — 클로드 코드 (권장)

`/tistory-convert` 스킬을 쓴다. 네이버 원고를 주면 판단 → 변환 → 검수까지
이어서 처리한다. 정의는 `.claude/skills/tistory-convert/SKILL.md`.

## 쓰는 방법 2 — 로컬 웹페이지

```bash
npm run tistory
```

브라우저에서 열리는 화면에서:

1. 네이버 제목·본문·핵심 정보·이미지 목록을 입력한다 (자동 저장된다)
2. `변환 프롬프트 생성` → 복사해서 클로드에 붙여넣는다
3. 클로드 결과를 `3` 칸에 붙여넣고 `HTML 변환 + 품질 검수`
4. 검수를 통과하면 `티스토리 HTML`을 복사해 티스토리 에디터의 HTML 모드에 붙여넣는다

`file://`로 직접 열면 ES 모듈이 막혀 동작하지 않는다. 반드시 위 명령으로 띄운다.

## 쓰는 방법 3 — CLI

```bash
# 입력 템플릿 생성
node tistory/qa-cli.mjs init input/naver_post.md

# 템플릿을 채운 뒤 변환 프롬프트 생성 → 클로드에 붙여넣기
node tistory/qa-cli.mjs prompt input/naver_post.md

# 클로드 결과를 저장한 뒤 검수 + 산출물 생성
node tistory/qa-cli.mjs check output/tistory_post.md \
  --naver input/naver_post.md --out output/
```

`--out`이 만드는 파일:

```
title_candidates.txt   제목 후보 3개
meta_description.txt   메타 설명
tags.txt               태그
tistory_post.html      티스토리 에디터에 붙여넣을 HTML (광고 위치 주석 포함)
image_plan.md          이미지 순서 + 광고 위치
metadata.json          프론트매터 + 검수 요약
```

`[수정]` 항목이 남아 있으면 종료 코드 1이다. CI나 스크립트에서 게이트로 쓸 수 있다.

## 품질 검수 항목

기획서 13장 체크리스트를 실행 가능한 검사로 옮긴 것이다.
판정은 `통과` / `확인` / `수정` / `직접` 네 가지고, `수정`이 하나라도 있으면
발행하지 않는다.

| 검사 | 기준 |
| --- | --- |
| 제목 완전 변경 | 네이버 제목과 동일하면 수정, 유사도 60% 초과면 확인 |
| 제목 후보 3개 | `title` + `title_alt` 합계 3개 이상 |
| 도입부 새로 작성 | 네이버 첫 문단과 유사도 45% 초과면 수정 |
| 핵심 키워드 배치 | 장소명/제품명이 제목과 첫 문단에, 지역이 제목에 |
| 메타 설명 | 120~160자 |
| 소제목 구성 | 4개 이상 |
| 태그 개수 | 5~10개 |
| 이미지 수 축소 | 네이버의 35~50%, 최대 15장. 네이버보다 안 줄면 수정 |
| 대표 이미지 | `hero_image` 지정 여부 |
| FAQ | 2~6개, 답변이 빈약한 항목 경고. 없으면 통과 (생략이 맞다) |
| 변동 정보 시점 표시 | 가격·운영시간 섹션에 "2026년 7월 기준" 류 문구 필수 |
| 수치 근거 대조 | 본문 수치가 원문/핵심정보에 없으면 경고 |
| 브랜드 단일화 | 과거 닉네임 8종이 남아 있으면 수정 |
| 네이버 원문 링크 | `naver_url`이 본문에 있는지 |
| 협찬 표시 | 협찬 글인데 표시 문구가 없으면 수정 |

`수치 근거 대조`는 `1만원` vs `10,000원` 같은 표기 차이에서 오탐이 난다.
그래서 `수정`이 아니라 `확인` 등급이다. 목록을 보고 판단한다.

## 파일 구조

```
lib/rules.js     규칙과 정량 기준의 단일 원본. 기준을 바꾸려면 여기만 고친다
lib/prompt.js    구조화 입력 → 변환 프롬프트
lib/render.js    초안 마크다운 → 티스토리 HTML + 광고 위치 마커
lib/qa.js        초안 파싱 + 품질 검수
index.html       로컬 웹 도구 화면
main.js          웹 도구 UI 로직
qa-cli.mjs       CLI (init / prompt / check)
```

프롬프트·렌더러·검수기가 모두 `lib/rules.js`를 읽는다. 이미지 권장 수나
메타 길이 같은 기준을 바꾸면 세 곳에 동시에 반영된다.

`render.js`는 범용 마크다운 렌더러가 아니다. 초안에서 실제로 쓰는 문법
(소제목·문단·목록·인용·표·이미지·링크·강조)만 지원한다.

## 지켜야 할 운영 순서

1. 네이버 블로그용 글을 먼저 쓰고 **발행한다**
2. 검색 수명이 긴 글만 골라 티스토리용으로 재가공한다
3. 티스토리 때문에 네이버 일정이나 영상 제작 일정이 밀리면 **티스토리를 생략한다**
4. 글당 추가 작업 10분 내외, 전체 작업 시간의 10~20%를 넘기지 않는다

기존 블로그 정리 작업은 [RELAUNCH-CHECKLIST.md](./RELAUNCH-CHECKLIST.md)에 있다.
